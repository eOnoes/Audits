## 8. Security and Integrity Review

Answers to the twelve focused boundary questions, with evidence.

1. Node upper bound. `windows-v3-metadata-node-clock-policy.mjs:10` computes `originNs = floor(originTicks·1e9/freq)` in BigInt; `:16` guard = 1 ms + `ceil(1e9/freq)`; `:21` denies samples below `originNs+guard+1` (too-fresh/future); `:25` reports `ceil((sample+guard−originNs)/1e6)`, saturating at 35,000 (`:26`). Upstream `uv__hrtime` (confirmed, `deps/uv/src/win/util.c`) is `(double)counter / ((double)freq/1e9)` truncated: two integer→binary64 conversions and two divisions, aggregate relative error < 2^-51 (< 4,096 ns for values < 2^63), so the 1 ms allowance dominates and the reading is an upper bound on true elapsed **given** (a) an unmodified runtime whose sampler is the captured `hrtime.bigint` (`node-clock.mjs:9`), (b) same host and boot so QPC epochs coincide, (c) the wire frequency equals the host's current `QueryPerformanceFrequency`, and (d) true nanoseconds < 2^63 (uptime < 292 years). Cast overflow: Node accepts only `1..2^63−1` for ticks, frequency and samples (`policy.mjs:5,9,21`); C# `Parse` bounds both to `Int64.MaxValue` (`host-clock-context.cs:30`); C# `Observe` uses exact `decimal` (`host-clock-policy.cs:31`). The accepted sample alone cannot establish (b), (c) or runtime provenance; version strings (`node-clock.mjs:10`) are not provenance. These are documented open gates.
2. Renewal. With `fromHostClock`, `startedAtMs` is fixed at 0 (`node-clock.mjs:54`) and ARM/session/report deadlines are `workMs`, `workMs+5000` from the original origin (`arm.mjs:24-26`, `session.mjs:22-29`, `report-session.mjs:16,24`); timers are `deadline − elapsed-at-construction` (`arm.mjs:30`, `session.mjs:31`, `report-session.mjs:28-31`) and every synchronous path re-reads the origin-based clock (`arm.mjs:32-38`, `session.mjs:34-40`, `report-session.mjs:35-39`). Re-instantiation over the same wire yields the same origin (`node-clock.mjs:38-40`; test `elapsed persists across delay and constructor recreation`). ARM receipt does not touch the deadline (`arm.mjs:60-63`). Report close keeps the original timer (`report-session.mjs:89-93`) and `takeCheckedReportWire` sets its one-use flag before any check and re-times around the copy (`:68-73`). Too-fresh denial and small budgets: see NB-4 (minimum usable Node reception budget is 4 ms). The default constructors measure from construction and are synthetic seams only.
3. Reaching a usable clock. Proxies, non-`Uint8Array`, `SharedArrayBuffer`, detached buffers and wrong lengths deny before any caller-controlled getter runs (`node-clock.mjs:15-22`, intrinsic getters); reference, host-session, nonce and work must match caller-supplied expectations (`:35-37`); the state is keyed by a module-private `WeakMap` and the class is sealed against subclassing and frozen (`:11,30,41,46`); binding mismatch or sample failure/regression latches the shared state invalid (`policy.mjs:21`, `node-clock.mjs:24,52`) with no reset path; an invalidated clock cannot be revived (test `bad, future, uncertain or regressing samples latch`). Public-method replacement is blocked by frozen prototype. Trusted-module/global boundary: everything loaded before this module and every global resolved at call time (NB-3); in-process same-realm code is fully trusted by design.
4. Agreement. OMK1 layout (`host-clock-context.cs:17-22`) is parsed identically by Node (`node-clock.mjs:34-38`, `history.mjs:78-84`); OMH2/OMW2 embed the same 128-byte OMK1 at offset 132 (`controller-clock-records.cs:14`, `watchdog-clock-records.cs:11`) and V2 history requires both intents to carry byte-identical OMK1 (`history.mjs:78`); the ARM V2 frame is built with identical key order and no whitespace in C# (`watchdog-clock-records.cs:25-28`), PowerShell (`watchdog.ps1:116-119`) and Node (`arm.mjs:27`, `session.mjs:78`); deadlines are work, work+5000, work+10000 everywhere (`host-clock.cs:22-23`, `watchdog.ps1:142,60`, `retained-watchdog.ps1:60`). An unkeyed checksum/reference proves only that bytes equal the bytes someone hashed; it does not prove who produced them, that they came from this host/boot, freshness, non-replay, or that the *expected* reference itself is authentic — the packet states this correctly.
5. Controller ordering. `MetadataControllerRetentionBridge.Reserve` (`controller-retention.cs:27-41`) → `ReserveClockBoundInApprovedHost` writes `.controller-intent-v2` with `CREATE_NEW` (`controller-clock-storage.cs:16`, `host-sink.cs:90`) and re-checks work liveness before returning; any later effect is the caller's, after return. `RecordAndClose` keeps `attempted`, `recorded`, `cleanup`, `failed` distinct and folds deadline/cleanup failures only into `LocalRetentionUncertain` (`controller-retention.cs:44-58`); a post-write deadline crossing marks uncertain without erasing the write. Report claims cannot be upgraded: snapshot properties are hard-wired false (`:12-15`), the bootstrap wire is validated structurally only (`bootstrap-report.cs:43-66`; Node parity `report.mjs:60-87`), and "reported" status never means verified.
6. Watchdog ordering. `WriteArm` requires the exact intent bytes to be re-read from storage and the original clock live before any arm byte (`retained-watchdog.cs:41-46`, `watchdog-retention.cs:15-19`); `FlushAndObserve` deliberately touches no storage (`:48-53`); in the wrapper, emergency stop runs in `Invoke-OnoesMetadataVmWatchdog`'s `finally` (`watchdog.ps1:138-168`) before `RecordClaims` (`retained-watchdog.ps1:48`). Blocking synchronous work: `Ready()` under lock inside `WriteAsync` (NB-6); `Get-VM`/`Stop-VM`/`Get-OnoesMetadataWatchdogTarget` have no cmdlet timeout; only the job wait is bounded (`:154`). No hard termination guarantee exists in-process.
7. Code holds. `MetadataHostCodeSet.OpenInApprovedHost` opens all three holds (`host-code-set.cs:25`) before any `TakeCheckedBytes` (`:26`) and holds them until `Dispose`; each hold is `FILE_SHARE_READ` only, `OPEN_EXISTING`, `FILE_FLAG_OPEN_REPARSE_POINT`, identity/ACL/stream-checked before and after the read (`host-code-hold.cs:60-62,72-79`).
